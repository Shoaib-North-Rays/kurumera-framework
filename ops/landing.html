Storefronts as code

Write a real Next.js storefront. Publish it per‑store.

A Kurumera theme is an ordinary Next.js app you keep in git. Run it against a live store's products and cart, push it, and the platform builds and serves it on that store's domain. Routing, checkout, payments and analytics are already handled.

Looking for a store preview?

This host renders a theme's build against a real store, so a preview needs to know which one: add ?store=<slug> to the URL, or open it with kurumera theme preview --store <slug>. Without a store it shows this page.

Two ways to build a storefront

For developers

A code theme, in your editor

A Next.js App Router project with a fixed route contract — home, product, collection, cart, search, page. You own every component. Read store data through @kurumera/storefront, run it locally against live products, and ship with the CLI.

From nothing to a live storefront

Seven commands. The only prerequisite is Node and an account with a store on it.

# install the CLI and sign in (opens a browser; use --device on a remote box) $ npm i -g @kurumera/cli $ kurumera login # scaffold a theme and see which stores you can act on $ kurumera theme init my-store $ cd my-store && kurumera stores list # run it against a live store's real products, at localhost:3000 $ kurumera theme dev --store my-store # validate, upload (the platform builds it), then make it live $ kurumera theme check ✓ theme check passed — no issues. $ kurumera theme push $ kurumera theme publish --store my-store ✓ Live and serving — https://my-store.kurumera.com

Keep it in git

A theme is just files. Commit before an upgrade so git diff tells you exactly what changed.

Upgrade without losing your work

kurumera theme upgrade reports first and writes nothing. --merge --from auto works out which CLI scaffolded the theme and three-way merges the template's changes into the files you edited; anything it cannot merge safely it names instead of guessing.

Roll back by version

Every push is retained. theme versions lists them, theme rollback restores the previous one, and theme pull --version downloads an exact version's original source.

Sell it, or buy one

marketplace publish lists your theme for other stores; marketplace clone downloads one to edit as your own.

What the platform already does

So a theme stays presentation and never grows a backend.

AreaWhat you get
store dataProducts, collections, search, cart and customer accounts over the storefront API, read through @kurumera/storefront. A theme needs no server of its own — custom API routes are rejected by theme check.
checkoutHosted and PCI-handled, with Stripe and cash-on-delivery. The cart hands off cleanly; the pages are yours to style. See the checkout guide.
analyticsPage, product, collection, search, cart, checkout and session events, with first-touch UTM and a durable visitor id. The tracker lives in the SDK so every theme reports identically.
formsA contact endpoint and custom forms per store, with spam protection and sender blocking. Show the server's message rather than your own — theme check flags a form that swallows it.
hostingPer-store builds, a wake-on-request preview, custom domains with TLS, and retained versions you can activate or roll back to.
multi-tenancyOne theme serves many stores. The store is resolved per request, so the same build renders each one's own catalogue and branding.
